# Decisions

Append new decisions; never silently reverse one. If a decision changes, add a new entry that references the old one and says what changed.

| Date | Decision | Reason | Consequences |
|---|---|---|---|
| 2026-10-21 | Build as a static site + GitHub Actions + JSON files; no server/database/framework | Free, simple, runs unattended; the user wanted a self-updating dashboard | No server-side auth; "backend" logic must run in Actions or the browser |
| 2026-10-21 | Phone data path: iPhone Shortcut using a third-party export app, uploaded to the repo via the GitHub API (not Google Drive, not iOS Files, not a native Find Health Samples shortcut) | Google Drive Files integration was unavailable on the phone; Actions cannot read iCloud/Files; the user did not want Health Auto Export; a hand-built native shortcut was judged too fragile (sleep grouping, JSON by hand); app + GitHub needs one token | Dependency on the export app's behavior (staged sleep only; late sleep) and on a GitHub token stored in the shortcut |
| 2026-10-21 | Drop Strava | API app creation requires a paid subscription | Only Hevy supplies workouts; `STRAVA_*` names are unused |
| 2026-10-21 | Hevy is read-only | User requirement ("make sure it only reads") | Code contains a single `GET`; keep it that way |
| 2026-10-21 | **Data is public**: public repo, public site, public `inbox/` | User explicitly accepted public data; free GitHub Pages requires a public repo. Alternatives (Cloudflare Pages+Access, encrypted data in a second repo) were offered; privacy options were re-raised later and left undecided | Anyone with the URL sees health data; keys must stay secret. If privacy is wanted later, see PROJECT_CONTEXT security section and the Cloudflare option |
| 2026-10-21 | Rename Stotis → **Motus** (repo, folder, site title); keep `localStorage` keys `stotis-*` | User request; keeping the keys preserves saved standards | Old Pages URL `/stotis/` is dead; phone shortcut URL should be updated (old URL redirects with 307) |
| 2026-10-21 | Minimalist design; black/white with green as the only accent; bright green on cards/table/charts, calmer dark green (`--green2`) in the Last Week line | User: "minimalism is the main point"; dark green so the summary is noticeable without taking attention | New UI must follow this; avoid extra colors (the 12-week chart colors were replaced by green/white) |
| 2026-10-21 | Timezone fixed to Asia/Riyadh (UTC+3, no DST); weeks start Sunday | User's location/preference; avoids tzdata on Windows | Hard-coded offset in `common.py` and `shared.js` (`TZ`) |
| 2026-10-21 | Averages are week-to-date (Sunday → today, inclusive), not rolling 7 days; "Last Week" = previous Sunday–Saturday | User request ("resets every Sunday") | Today's partial steps lower the early-week steps average (open question) |
| 2026-10-21 | Weight card uses latest-vs-previous reading change per week; Last Week line uses average-vs-average | User asked that the last-week summary be averages; top card left as is | Two definitions of "weight change" exist (see KNOWN_ISSUES) |
| 2026-10-21 | Standards are stored per device (`localStorage`); default steps 8000, sleep 7 h, calories < 1500, weight loss any, workouts/week 4 | No backend; user wanted editable standards that recolor the dashboard | Visitors can change their own view only; "lock the panel" was offered and **not answered** |
| 2026-10-21 | Training days default Mon/Tue/Wed/Fri/Sat, editable in Standards | User listed the days | Weekly goal (4) differs from planned days (5); user has not changed it |
| 2026-10-21 | Ratings use the project's own Epley e1RM from Hevy sets (Hevy provides no 1RM); compare each exercise with its own recent history; ignore bodyweight/warm-up/>12-rep sets | Most lifts are machine/dumbbell, so bodyweight-ratio strength standards do not apply | Bodyweight exercises are never rated |
| 2026-10-21 | Overall rating = 0.7 Progress + 0.3 Consistency; breakdown lines hidden from the UI | Initial design; the user did not understand the breakdown lines and asked to remove them | Number remains but is hard to explain on the page |
| 2026-10-21 | New exercises (fewer than 2 earlier sessions) are not counted; score is the average of exercises with data | User request | A workout with ≤ 1–2 rated exercises is noisy |
| 2026-10-22 | **Per-workout scale changed**: 7 = normal session (within 5% below recent level), +0.3 per 1% up to 10, −0.8 per 10% below the band, floor 3; baseline window limited to 90 days. Supersedes the first scale (5 = baseline, 0 at −5%) | User: a −8% lift gave 0.0, and "0 means I didn't even train" | Per-workout scores now mostly 6–9. The overall Progress score still uses the old scale (flat = 5) — inconsistency recorded in KNOWN_ISSUES |
| 2026-10-22 | Fix missing morning run: 3 off-peak cron entries; `status.json`; fail the run on source errors; staleness banner | No scheduled run had ever fired; nothing detected missing data | Runs are idempotent and commit nothing when unchanged |
| 2026-10-22 | **Manual corrections via a validated GitHub workflow** (`workflow_dispatch`), stored in `overrides.json`; admin token with Actions-only scope | GitHub Pages has no server; GitHub's own write-access check is the only real server-side authorization available without new infrastructure | Edits take ~1 minute (run + deploy); corrections are public; GitHub notifies on failed runs |
| 2026-10-22 | **Correction rule**: a correction always wins over automatic sync; the automatic value is kept in `orig` and keeps refreshing; reverting restores the latest automatic value; `null` correction = "no data" | User requirement: corrections must not be silently overwritten and must be revertable | Corrected days stay corrected until reverted, even if better automatic data arrives |
| 2026-10-22 | `data.json` `updated` moves only when content changes; workflow commits only on change | Avoid empty bot commits now that the job runs 3×/day | The footer reads "Data changed …", not "Updated …" |
| 2026-10-22 | GitHub is the source of truth: `CLAUDE.md` + `docs/` maintained with every change, commit and push by default | User requirement | See the mandatory workflow in `CLAUDE.md` |
| 2026-10-22 | **Schedule changed to every 3 hours (`17 */3 * * *`)**, superseding the three fixed daily slots chosen earlier the same day; footer shows each source's last delivery | A workout logged today was not in Hevy's cloud yet (finished/synced later); frequent runs pick it up within hours without manual action. Cost is negligible (public repo; runs commit nothing when unchanged) | ~8 runs/day, ~34 Hevy API calls per run |
| 2026-10-22 | **Week-to-date averages by metric**: steps and calories Sunday → *yesterday*; sleep and weight Sunday → *today*. The weight card becomes this week's average minus last week's average. Supersedes the 2026-10-21 rows "Averages are week-to-date (Sunday → today, inclusive)" and "Weight card uses latest-vs-previous reading change" | User: today's steps and calories only show the first part of the day, so they would drag the average down; a night's sleep and a morning weigh-in are complete. Averages also stop the weight card swinging with a single weigh-in | On a Sunday, steps and calories show "no data" until Monday. The rule is one tested function (`weekAvg` in `site/shared.js`); `daily.py` does not compute averages |
| 2026-10-22 | Dashboard heading is **"Weekly avg (Since Sun, 18 Oct)"** (the week's Sunday date, short month); the earlier clause "steps and calories to yesterday" was dropped. Supersedes the heading wording chosen earlier the same day | User request (shorter, clearer) | The page no longer explains that steps/calories exclude today; the rule is in the docs and `weekAvg` |
| 2026-10-22 | **Weekly history is derived from `data.json` on every run** (completed Sunday-Saturday weeks), written to `weeks.json` + `WEEKLY_STATS.md`; not a sealed append-only snapshot | User wanted a file of weekly stats that gains a row when each week ends. Deriving it keeps it consistent with late syncs (Saturday's data often arrives on Sunday) and manual corrections, and cannot lose history because `data.json` keeps every day | An old week can change if its underlying days are corrected later; the file is regenerated, never hand-edited |
| 2026-10-22 | Nav is always four items (Dashboard, Workouts, Weeks, Standards); the admin "Edit data" link moved into the Standards panel; nav spacing tightened below 360 px | Adding "Weeks" made the nav overflow at 320 px (even for visitors) | Admin must open Standards to reach Edit data (or use the table's day links) |
| 2026-10-26 | **Streaks line**: Hevy total workouts comes from Hevy's API count (`status.json`); the logging streak is **computed from our own calories data** (consecutive days with calories > 0; today does not break it; capped flag when it reaches the first day of our data). MyFitnessPal's own streak is **not imported** | User: "from hevy add the total workouts done till now, and from myfitnesspal tell me how to get the total daily count streak". Neither MyFitnessPal documentation nor any export that includes a streak could be found, and its public API is reportedly closed, so the number cannot be read automatically | Our streak may differ from the app's (their definition is unknown; partial days such as 500 kcal count as logged; it starts at 1 Sep because that is where our data begins). If the owner reads the app's number, it can be added as a manual baseline |
| 2026-10-26 | The weight card shows the week's **average weight** on its own line under the change | User: "add the average weight as well next to the total lost" | Card sub-text is two lines (same height as the calories card) |
| 2026-10-26 | **The average weight is removed from the weight card** again: it shows only how much was lost/gained. Supersedes the 2026-10-26 row "The weight card shows the week's average weight on its own line" | User: "don't add the average weight I just said just remove it and make it like it was before only how much lost" | The weight card is exactly as before; the average weight remains visible in the Last Week line and on the Weeks page |
| 2026-10-26 | **Streaks live in their own section at the very end of the dashboard** as two tiles (flame + 4-week calendar; dumbbell + 12-week mini chart), replacing the one-line version under Last Week | User: "make the streaks all the way to the end ... add it in a fancy way. not like this." | Adds an icon-and-chart section; still black/white with green as the only accent |
